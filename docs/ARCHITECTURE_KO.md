# ModueAgent 보안 아키텍처 명세서

이 문서는 **ModueAgent** 프레임워크의 내부 구조, 위협 모델, 그리고 제로 트러스트 보안 경계를 상세히 설명합니다.

🌐 **Language: [English](ARCHITECTURE.md) | [한국어](ARCHITECTURE_KO.md)**

---

## 1. 위협 모델 및 보안 경계

ModueAgent는 LLM의 모든 입력이 적대적이고 신뢰할 수 없는 환경을 전제로 설계되었습니다.

### 1.1 방어 대상 위협 유형

1. **간접 프롬프트 주입 (Indirect Prompt Injection, IPI)**:
   - 외부 웹 크롤링, 써드파티 데이터베이스, 사용자 업로드 파일 등에 숨겨진 악성 자연어 페이로드.
   - *방어책*: 엄격한 도구 화이트리스트(`allowed_tools`), 정밀 JIT 역량 토큰, `EffectClass.DESTRUCTIVE` 사전 검증 트랩.
2. **혼동된 대리인 문제 (Confused Deputy Problem)**:
   - LLM이 사용자의 적법한 권한을 갖고 있으면서도, 공격자의 지시대로 행동하여 권한을 오남용하는 문제.
   - *방어책*: L1 전송(`TRANSPORT`)과 L2 실행(`RESOURCE`) 스코프 분리, 권한 위임 시 감쇠(Attenuation) 규칙 강제.
3. **정보 유출 및 시크릿 탈취 (Information Disclosure)**:
   - 도구 실행 원본 결과에 포함된 API 키, 환경변수, 내부 IP가 프롬프트 컨텍스트로 흘러들어가 유출되는 문제.
   - *방어책*: `extract_safe`를 통한 XOA 실행 전용 출력 필터링 및 **원본 데이터 메모리 즉시 폐기**.
4. **원격 코드 실행 (Arbitrary Code Execution, RCE)**:
   - 샌드박스 없는 수식 평가나 터미널 셸 도구 실행으로 인한 호스트 장악.
   - *방어책*: AST 노드 화이트리스트 기반 안전 연산기(`safe_eval_arithmetic`); `eval()`, `exec()`, 셸 실행 함수 원천 배제.
5. **과금 테러 (Denial of Wallet, DoW) 및 자원 고갈**:
   - 공격자가 유도한 악성 무한 루프로 인해 API 크레딧이 전액 소진되는 문제.
   - *방어책*: 스텝 상한선(`max_steps`) 및 토큰 상한선(`max_tokens`) 하드 스톱 회로 차단기.

## 2. 핵심 아키텍처 컴포넌트

```text
+-------------------------------------------------------------------------+
|                        인지 계층 (신뢰할 수 없는 영역)                   |
|                                                                         |
|  [사용자 입력] ──> [대화 히스토리] ──> [LLM 추론 엔진 / 플래너]          |
+------------------------------------+------------------------------------+
                                     | 도구 실행 의도 (ToolCallRequest)
                                     v
+------------------------------------+------------------------------------+
|               보안 & 역량 제어 커널 (신뢰 영역)                         |
|                                                                         |
|  1. 입력 JSON Schema 검증 (_validate_tool_arguments)                    |
|  2. 에이전트 도구 화이트리스트 검사 (allowed_tools)                     |
|  3. JIT 최소 권한 토큰 발급 (CapabilityEngine)                          |
|  4. 파괴적 작업 검증 트랩 (Verification Trap / HITL)                     |
+------------------------------------+------------------------------------+
                                     | 샌드박스 호출
                                     v
+------------------------------------+------------------------------------+
|                      도구 실행 샌드박스 (격리 영역)                      |
|                                                                         |
|  [도구 함수] ──> [원시 출력] ──> [XOA extract_safe] ──> [필터링된 결과]  |
|                                         │                               |
|                                         └──> (원시 데이터 영구 파기)     |
+-------------------------------------------------------------------------+
```

### 2.1 역량 엔진 (`modueagent.capability`)
- 객체 역량(Object Capability) 모델을 구현.
- 모든 토큰은 불변 객체(`@dataclass(frozen=True)`).
- 스코프를 `TRANSPORT`(통신 접근)와 `RESOURCE`(자원 실행)로 엄격히 분리.
- `tool:*` 와일드카드 발급 시도 시 즉시 거부 (와일드카드 금지 불변식).

### 2.2 보안 가드레일 (`modueagent.guardrails`)
- `safe_eval_arithmetic`: 파이썬 `ast` 모듈을 사용해 사전 승인된 사칙연산자와 상수만 순회 평가.
- `extract_safe`: 코드 실행 없이 순수 딕셔너리 키와 리스트 인덱스만 탐색하는 안전한 파서.
- `mask_error`: 시스템 내부 스택트레이스와 파일시스템 절대경로 은닉.

### 2.3 런타임 엔진 (`modueagent.runtime`)
- ReAct 실행 루프를 안전하게 조율.
- 도구 호출 시점에만 JIT 단기 토큰을 발급하고 실행 직후 즉시 회수.
- 스텝/토큰 예산 초과 시 즉각 중단하고 안전한 부분 요약 답변(`_synthesize_partial_answer`) 생성.
